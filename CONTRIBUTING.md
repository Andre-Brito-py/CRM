All rights are reserved. Any unauthorized copying, distribution, or modifications of this codebase, via any medium, is strictly prohibited.

## Internal Development Guidelines

If you are a member of the internal development team contributing to this project, please follow these guidelines:

1. **GitHub Flow:** All code changes must happen through Pull Requests. 
2. **Branching:** Create your feature or bugfix branch from `master` or `develop` (e.g., `feature/my-new-feature` or `bugfix/issue-description`).
3. **Tests:** If you have added logic or components that should be tested, write unit or integration tests as appropriate.
4. **Linting:** Ensure your code matches the project's styling and lints successfully by running `npm run lint`.
5. **Pre-commit Checks:** Verify that the project builds correctly locally before opening a pull request.
